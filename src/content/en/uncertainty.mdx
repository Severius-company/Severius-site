# From uncertainty to a buildable software project

An idea becomes buildable when it stops being framed as a feature list and starts being described as an observable change.

## Start with what needs to change

Record the context, who experiences the problem and which friction deserves attention. Separate available evidence from assumptions. That distinction prevents familiar tools from deciding the solution too early.

## Define a useful criterion

A first release does not need to solve everything. It needs to enable a better decision. Define what useful looks like, which risks cannot be ignored and what evidence will be enough to continue.

## Build to learn

The smallest reliable solution connects the problem, the criterion and observation. After it, the team can keep, adjust or stop a direction without relying on an optimistic story.
